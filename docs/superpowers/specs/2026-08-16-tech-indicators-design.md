# 持仓技术指标弹层

日期：2026-08-16

## 背景

持仓页已经能说清账户现状和「看一只」。使用者希望对**已经持仓**的一只，点名称打开技术分析：不仅列数字，还要白话解读，并给出带依据的倾向。判断可以偏买或偏卖，但不能只有结论没有论证。

## 目标

- 点击持仓名称（如「半导体设备ETF华夏」）打开本机技术页（非整页弹层；见 market-context 规格修订）。
- 点开时再拉日 K、计算 easy-tdx 可算的全部指标（约 34 个）。
- 有信号的指标默认展开（解读 + 数字依据）；其余默认折叠。
- 顶部一句总倾向（更宜观望 / 更宜谨慎加仓 / 更宜先减一点等），必须带依据。判断可以偏买或偏卖，但不能只有结论没有论证。

## 非目标

- 刷新持仓时预计算全部指标。
- 给未持仓代码做同款弹层（「看一只」另走）。
- 教指标公式、画完整副图。
- 缠论、回测当无依据的实盘口令。
- 登录券商或自动下单。

## 交互

1. 持仓卡标题链到 `/tech/{code}`（本页跳转）。
2. 技术页顶有「返回持仓」。
3. 不再使用遮罩弹层。
4. 同一会话内同一代码可短时缓存结果（可选，不强制）。

## 接口

- `GET /tech/{code}`（或等价 POST）：`code` 必须是当前 `holdings.json` 里已有的代码，否则 404。
- 服务端：easy-tdx 拉约 120 根日 K → `compute_indicators` / MyTT 算库内全部指标 → 规则引擎产出「信号 / 解读 / 总倾向」。
- 场外基金若无可用日 K：弹层写明「这只没有够用的日 K，算不了技术指标」，不伪造。

## 弹层结构

1. 名称、代码、现价（有则显示）
2. **总倾向**一句 + 依据列表
3. **有信号**分组：每条 = 指标名 + 白话解读 + 关键数字
4. **其余**分组：折叠；展开后同样有短解读和最新值

## 总倾向规则（B+C）

从有信号条目汇总：

- 多空明显一边倒 → 「更宜谨慎加仓」或「更宜先减一点」（措辞克制）
- 信号少或打架 → 「更宜观望」
- 每条总倾向下必须列出用到了哪些信号作依据
- 禁止：只有「立即买入/卖出」没有依据；禁止「一定涨/跌」

## 「有信号」判定（写死，可后续加）

至少覆盖常见项（有则标为有信号）：

- MACD：金叉 / 死叉 / 柱由负转正或由正转负
- KDJ：K/D 超买或超卖区，或金叉死叉
- RSI：超买或超卖
- 布林：收盘接近或跌破下轨 / 突破上轨
- 均线类（若产出）：多头或空头排列、价格站上/跌破关键均线
- 其它指标：仅当落入该指标常用阈值（如 CCI、WR 超买超卖）时记为有信号；否则进「其余」

解读用白话：偏强、偏弱、偏热、偏冷、说法不一致；可出现 MACD、KDJ 等名字，不展开公式课。

## 实现分层

- `market`：按代码取日 K（已有持仓行情路径复用）
- `tech`（或 `indicators`）：纯函数，吃 K 线 → 指标值 + 信号列表 + 总倾向
- `web`：路由 + 模板弹层 / 少量 JS 打开关闭与请求
- 测试：信号判定与总倾向用固定假数据；不依赖外网

## 用语

股票、基金、代码、现价、判断、依据；倾向只用「更宜…」句式。不造产品黑话。

## 验收

1. 点已持仓名称出现弹层，有总倾向和依据。
2. 有信号项展开有解读；折叠区能打开看到其余指标。
3. 非法 / 未持仓代码不能靠改 URL 随便算（或明确拒绝）。
4. 无日 K 时有明确说明，页面不崩。
5. 每条判断下面都有依据，不是只有一句买卖。
